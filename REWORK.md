## 2. Прайс (OpenRouter)

Источник цены переведён с каталога на список эндпоинтов слага; политика выбора
вынесена в конфиг и показана в UI. Остальное — тариф и матчинг — не тронуто.

- [ ] **Починить `rstrip(":free")`** — `app/matcher.py:116` и `app/matcher.py:228`.
      `str.rstrip` режет **набор символов** `{: f r e}`, а не суффикс: `...-large` → `...-larg`,
      `...-reranker` → `...-rank`. Заменить на `removesuffix(":free")`.
- [ ] **Починить дедупликацию индекса.** `app/matcher.py:128`: `if n and or_id not in by_norm`
      — проверяется `or_id` в словаре, ключуемом по `n`; условие практически всегда истинно,
      и модель с тем же нормализованным именем затирает предыдущую. Должно быть
      `n not in by_norm` + осознанный выбор победителя (самая дешёвая / самая свежая).
      **Подорожало после оживления Layer 3** (§1): 5 моделей (`gemma-4-31b`,
      `gemma-4-26b-a4b`, `qwen3-235b-a22b-no-thinking`, `deepseek-v4-flash-high-preview`,
      `nvidia-nemotron-3-super-120b-a12b`) находят `or_id` третьим слоем, но этого id
      нет в обратном индексе `by_norm` → цена не резолвится и модель уходит в unmatched.
- [x] **Не выбрасывать бесплатные модели.** Отсекающие условия `prompt > 0` убраны
      (оба были мёртвым кодом: `fetch_prices` никто не звал, а `prices` в воркере
      никто не читал), `:free` доезжает до таблицы. `None` при `price <= 0` закрыт
      в §3: цена поднимается до `price_floor_1M` = 0.01 $/1M (чуть ниже самой
      дешёвой платной модели рынка, $0.025), и обе `:free`-модели категории
      `overall` получают value и встают в топ. Побочный эффект: если в категории
      есть бесплатная модель, шкалу (лидер = 100) задаёт именно порог из конфига.
- [ ] **Брать полный тариф.** Сейчас читаются только `prompt` / `completion`.
      Игнорируются `internal_reasoning` (критично для thinking-моделей), `input_cache_read`,
      `input_cache_write`, `request`, `image`. Решить, что входит в цену, и задокументировать.
      Данные для этого уже под рукой: те же поля лежат в `pricing` каждого эндпоинта
      (`app/sources/openrouter.py:_endpoint`), достаточно расширить `Endpoint`.
- [x] **Разобраться с несколькими провайдерами на модель.** Цена берётся из
      `GET /models/{slug}/endpoints`, а не из каталога: каталожный тариф — это тариф
      дефолтного эндпоинта. Замер на живом API (2026-09-07, выборка 41 модели):
      у 51% моделей провайдер не один, у 7 из 21 мультипровайдерных каталог завышал
      цену на 10-180%. На проде из 175 слагов категории `overall` цена изменилась
      у 32 — до −60% (`llama-3.1-8b-instruct` $0.05 → $0.02).
      Политика в `config.yaml` (`sources.openrouter.price`): `min` (по умолчанию) /
      `median` / `catalog`. Критерий сопоставимости — **те же веса, что мерила арена**:
      тиры обслуживания в выборе участвуют (`openai/flex` за $1 — та же модель, что
      `openai` за $2, только в отложенной очереди, и эту цену реально можно заплатить),
      а урезанные веса `fp4`/`int4` исключены — это уже другая модель.
      На `overall` цена ниже каталожной у 52 моделей из 175: флагманы вдвое
      (`gpt-5.5` $5.00 → $2.50 на flex), открытые до −60%
      (`llama-3.1-8b-instruct` $0.05 → $0.02 на fp8 DeepInfra), при этом fp4-дно
      отвергается (`qwen3.8-27b` берёт $0.24 fp8, а не $0.15 fp4).
      В строку снапшота пишется `price_source` (провайдер, тег, квантизация,
      сколько эндпоинтов сопоставимо из скольких, разброс blended min-max);
      в UI это колонка Provider с подсказкой, значок `≈` помечает цену вне
      сопоставимого набора.
- [ ] **Ограничить fuzzy-матч.** Layer 4 (`app/matcher.py:189-198`) матчит между организациями
      при ratio > 0.85 — риск привязать цену чужой модели без единого сигнала. Сохранять в
      снапшот `match_layer` и `match_confidence`, показывать значком в таблице;
      Layer 4 либо выключить, либо явно помечать как ненадёжный.
- [ ] **`created` ≠ дата релиза модели.** Это дата добавления в OpenRouter
      (`app/matcher.py:129`). Из формулы зависимость убрана (§3: медиана считается
      по рейтингу, а не по свежести), но поле осталось в снапшоте и в сортировке
      таблицы по дате — там оно по-прежнему врёт. Найти корректный источник даты
      или переименовать колонку.
- [ ] **Санити-чек цен.** Отбрасывать или логировать заведомо аномальное ($0.0001 у флагмана,
      $500/1M) — сейчас любая мусорная цена молча улетает в формулу. Половина данных
      для этого появилась: `price_source.min_blended_1M` / `max_blended_1M` дают разброс
      по слагу, и аномалия видна как выброс относительно собственного слага. Фильтра
      или лога всё ещё нет.

## 3. Формула Value Score

Метрика переопределена: цена приводится к качеству (`effective_price`, $/1M) и
нормируется внутри категории на медиану (медианная модель = 100). Спека, README
и UI переписаны под код. Не тронуты `token_share`, подбор `k`/`γ` и тесты.

- [x] **Синхронизировать SPEC / README / код.** Врал `README.md`: «win probability
      (Elo) × blended price» с весами `β/γ`, которых нет ни в коде, ни в
      `config.yaml` (там `k/γ`). Формула переписана в `SPEC.md` §2, `README.md`,
      `README.ru.md` и в модалке дашборда (`static/index.html`), везде одна и та же.
      Заодно из диаграмм и таблицы компонентов убрано `win probability`.
- [x] **Определиться, что такое медиана.** Выбран вариант `SPEC.md`: медиана
      **топ-N по рейтингу** (`scoring.median_top_rating`). Отбор «самых свежих за
      60 дней» удалён вместе с `TWO_MONTHS`: он опирался на `created` =
      дату появления слага в каталоге OpenRouter (см. §2), то есть якорь метрики
      зависел от того, когда модель завели у посредника.
- [x] **Ограничить взрыв на дешёвых моделях.** Три правки в `app/scoring.py`:
      нижняя граница цены `price_floor_1M` (0.01 $/1M, конфиг) — `price → 0`
      больше не даёт бесконечность; нормировка внутри категории; `exp` клампится
      по `MAX_EXPONENT` вместо ветки `OverflowError` с магическим `1e9`.
- [x] **Убрать зависимость шкалы от одной строки.** Нормировка на минимум
      (`value = 100·(price_eff_min/price_eff)^γ`) держалась на одной произвольной
      модели, и на снапшоте 2026-09-08 ею оказалась `thinkingmachines/inkling:free`
      с ценой $0 → в метрику шёл сам `price_floor`. Сотню забрала константа
      конфига, а весь фронтир сплющился: `claude-fable-5` 3.1, `claude-opus-4.6`
      4.4, `gemini-3.8-flash` 15.2 при `balanced`. Проверка чувствительности:
      floor 0.001 давал `fable-5` **0.99**, floor 0.05 — **7.02**, при одном и том
      же состоянии рынка.
      Две правки. (1) Строки, чью цену подменил порог, помечаются
      `scoring.price_is_floored` и **исключаются из выборки якоря** (в таблице
      остаются, помечены звёздочкой). (2) Якорь — **медиана** `price_eff`
      (`scoring.anchor_effective_price`), а не минимум: медиану не сдвигает
      появление одной аномально дешёвой модели.
      Цена решения — шкала перестала быть ограниченной сотней: 100 = медианная
      модель категории, выше — выгоднее её. На том же снапшоте (`overall`,
      `balanced`) стало: `glm-5.3-flash` 367, `gemini-3.8-flash` 161,
      `claude-opus-4.6` 47, `claude-fable-5` 33, `inkling:free` 1064*.
      Низ на `γ = 1.0` по-прежнему уезжает на порядки — это вопрос шкалы
      **отображения** (лог-ось для баров и цвета точек) → §4/§5, а не формулы.
- [ ] **Сделать значение интерпретируемым.** Со стороны метрики сделано:
      value — «сколько процентов от эффективности медианной модели категории», а рядом
      в снапшот пишется `effective_price_1M` по каждому пресету — цена в долларах,
      приведённая к рейтингу медианы («столько стоила бы модель, будь она уровня
      медианы»). Осталось UI: `effective_price_1M` отдаётся по API, но колонки в
      таблице для неё нет, объяснение живёт только в модалке (§5).
- [ ] **Пересмотреть `token_share: 0.75`** (`config.yaml:22`). У reasoning-моделей соотношение
      вход:выход другое; сделать параметром UI (слайдер) или пресета, а не глобальной константой.
- [x] **Проверить пресеты на реальных данных.** `k` и `gamma` были подобраны
      на глаз. Замер на снапшоте 2026-09-08 (`overall`, 175 моделей): пресеты не
      бессмысленны, но и не независимы — τ Кендалла 0.66–0.84, в топ-10 совпадают
      6–8 моделей из 10, и все три топа состоят из дешёвых flash-моделей.
      **Главное, что вскрылось:** `γ` **не влияет на порядок строк вообще** —
      `ln value = γ·(kΔ − ln price) + const`, а возведение в положительную степень
      монотонно. Весь трейд-офф «качество против цены» сидит в одном `k`, а `γ`
      только растягивает шкалу.
      `k` получил эмпирический ориентир: `scoring.market_price_slope` считает
      наклон `ln(price)` по рейтингу на самих данных и пишет его в снапшот
      (`calibration.<вкладка>.market_slope`, отдаётся в `/api/meta`). На
      2026-09-08 рынок берёт 0.0054–0.0069 за очко (`overall` 0.0069, R² 0.16),
      то есть `budget` идёт вровень с рынком, `balanced` в ~1.5 раза круче,
      `quality` — в ~2.2 раза. Текущие значения оказались не случайными.
- [x] **Разобраться, почему `k` не работает в верхушке.** Выглядело как
      недокрут `k`: в топ-10 `overall` value ранжирует практически по цене —
      `claude-fable-5` 33 против `gemini-3.8-flash` 161 при разрыве в 13 очков
      рейтинга и 26× по цене. Оказалось, что подбором `k` это не лечится.
      Разрыв топ-10 (20.4 очка) сопоставим с шириной доверительного интервала
      (медианная полуширина ±5.0, полоса неразличимости ±7): **25 пар из 45
      внутри топ-10 статистически неразличимы**, включая все четыре верхние
      строки. Усиливать этот разрыв — усиливать шум, и одним `k` это не
      локализуется: `k = 0.035` даёт в верхушке 2.04×, но полный размах
      категории (417 очков) при этом уходит в 2.2 млн× (таблица в `SPEC.md` §2).
      Сделано другое: в метрику идёт **нижняя граница 95% CI**
      (`scoring.rating_for_metric`, `scoring.rating_basis: lower`) — модель не
      получает кредит за лидерство, которого не доказала числом голосов.
      Колонки `rating_lower`/`rating_upper` теперь читаются из датасета
      (`_WANTED_COLUMNS`), проходят через матчер в снапшот и показываются в
      таблице как `±`. Эффект тем сильнее, чем шире интервалы: в `overall`
      (медианная полуширина ±4.6) сдвинулись 72 строки из 175, максимум на
      6 позиций; в `math` и `research` (±13.4) — 142 и 148 строк, максимум на
      13. Страдают строки с широким CI (`glm-4.5v` 104 → 117 в `research`),
      выигрывают заголосованные (`gemini-2.5-flash`, ±2.5 при 122 781 голосе,
      54 → 48 в `overall`). Верхушку это почти не двигает — там разрывы и так
      внутри шума, — так что исходный симптом («в топе ранжирует по цене»)
      никуда не делся: он не баг, а то, что говорят данные.
- [ ] **Написать тесты на `scoring.py`.** Проверки прогнаны разово скриптом
      (монотонность по рейтингу и по цене, `price = 0` → пол, отрицательная и
      `NaN` цена → `None`, экстремальный Δ без `OverflowError`, медиана по рейтингу,
      инварианты снапшота) — в репозиторий не занесены, `pytest` по-прежнему нет.
      Ветки `OverflowError` больше не существует, вместо неё кламп `MAX_EXPONENT`.

## 4. График (scatter)

теперь всё рисуется одним SVG, HTML остался только у тултипа (текст с
переносом и авто-высотой в SVG не сверстать).

- [x] **Логарифмическая ось X.** Цены расходятся на 3 порядка ($0.01 … $75), на линейной

- [x] **Защита от деления на ноль.** Вырожденные домены (одна модель, одинаковые цены

- [x] **Честный Парето-фронт.** `scPareto` (`static/index.html:825`): модель на фронте,
      если ни одна более дешёвая не имеет рейтинг не ниже. Рисуется ступенькой — до

- [x] **Вторая производная убрана.** Зелёного пунктира больше нет.
- [x] **Разнесены подписи.** Жадное разрешение коллизий: 4 позиции вокруг точки,
      проверка пересечений с уже размещёнными подписями и со всеми точками, что не
      влезло — остаётся без подписи (имя доступно по ховеру/тапу). Вместо подложки —
      обводка фоном через `paint-order`, она не перекрывает соседей.
- [x] **Ререндер при resize.** Геометрия (`cw`, `ch`) читается из DOM на каждой отрисовке,
      выборка хранится в `scatterState`, `ResizeObserver` перерисовывает через `rAF`
      (`static/index.html:1247-1263`). Высота `#sChart` различается по брейкпоинтам
      (600/400/320px) — захардкоженные `ch = 600` выносили нижнюю треть точек за карточку.
- [x] **Одна технология рендера.** Сетка, оси, точки, подписи, фронт и легенда — SVG;
      область построения обрезана `clipPath`.
- [x] **Легенда для цвета.** Градиентная шкала VALUE с границами диапазона в правом
      верхнем углу. Палитра — viridis, обрезанная снизу (тёмный конец сливался с фоном
      `#0f1117`): монотонна по светлоте, читается при дальтонизме и в ч/б.
- [x] **Мобильная версия.** Тап по точке показывает тултип и подсвечивает её, тап мимо —
      прячет (`pointerover` только для мыши, `click` для всех). Хит-зона 14px вместо
      6px радиуса точки, тултип держится за точку и клампится в границы карточки.
      Подписи на узких экранах не рисуются осознанно — имена доступны по тапу.
- [x] **Клиппинг выбросов.** Координаты клампятся в область построения, группа с точками
      и подписями обрезана `clipPath` — рисовать поверх осей больше нечем.

- [x] **Шкала цвета по `value`.** Считалась линейно, и распределение перекашивало
      её: бесплатные модели забирали верх шкалы, вся платная часть красилась
      нижней третью градиента. После перехода value на нормировку к медиане
      (§3) стало хуже — шкала перестала быть ограниченной сотней, и `:free`
      уходили за 1000. Общий хелпер `valueDomain`/`valueFraction`
      (`static/index.html`): домен логарифмический (value — отношение, а не
      доля, одинаковые отрезки должны отвечать одинаковым отношениям) и
      строится **по платным строкам** — по той же причине, по которой они одни
      идут в якорь метрики. Строки с `price_is_floored` рисуются во всю ширину
      и помечены звёздочкой. На срезе 2026-09-08 (`overall`, 15 точек) градиент
      снова разошёлся на всю палитру: 32 → 158 по легенде, 15 различимых цветов
      на 15 точек.
