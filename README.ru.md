# LLM Price Arena

Сервис аналитики соотношения качества и цены LLM-моделей. Агрегирует Elo-рейтинги из **LMArena** и цены инференса из **OpenRouter**, вычисляет параметризуемый **Value Score** и предоставляет результаты через **REST API** и **статический дашборд**.

Полная спецификация: [`SPEC.md`](./SPEC.md)

---

## Обзор

LLM Price Arena — инструмент мониторинга и сравнения, который:

- Загружает **Elo-рейтинги** из датасета HuggingFace `lmarena-ai/leaderboard-dataset` (категории: overall, coding, math, research, agent)
- Получает **поценовую стоимость токенов** из публичного реестра моделей OpenRouter
- Сопоставляет имена моделей между двумя источниками через конфигурируемую таблицу алиасов
- Вычисляет **Value Score** — цену, приведённую к качеству (Elo) и нормированную внутри категории на медианную модель, которая получает 100
- Атомарно кэширует результаты и обновляет их по расписанию через APScheduler
- Отдаёт данные через FastAPI-приложение с фоновым воркером

## Формула Value Score

Метрика считается в две ступени: сначала цена приводится к качеству, потом
нормируется внутри категории.

```
quality   = rating_lower  (rating_basis: lower)             # нижняя граница 95% CI
M_top_N   = median(top_n лучших по quality)                 # якорь Δ
Δ         = quality - M_top_N                               # расстояние до якоря
price     = token_share × input + (1 - token_share) × output    # $/1M, средневзвешенная
floored   = price < price_floor_1M                          # цену подменил порог
price     = max(price, price_floor_1M)                      # :free не делит на ноль
price_eff = price × e^(-k·Δ)                                # $/1M при качестве якоря
P_anchor  = median(price_eff по строкам с floored = false)  # якорь шкалы value
value     = 100 × (P_anchor / price_eff)^γ                  # 100 = медиана категории
```

- **`price_eff`** — «сколько стоила бы модель, будь у неё рейтинг якоря».
  Остаётся в долларах и пишется в снапшот как `effective_price_1M` по каждому
  пресету: это то, что читается глазами, в отличие от индекса.
- **`value`** — «сколько процентов от эффективности медианной модели
  категории». 100 — как у медианы, больше — выгоднее её, меньше — дороже.
  Сверху не ограничен, сравним **внутри одной категории и одного пресета**.
- Якорь шкалы — **медиана, а не минимум**. Минимум держала одна произвольная
  строка, поэтому одна аномально дешёвая модель двигала value всем остальным:
  на снапшоте 2026-09-08 сотню забрал `thinkingmachines/inkling:free`, и весь
  фронтир сплющился в 3–4 балла.
- Строки с `floored = true` (`price_is_floored` в снапшоте) **в выборку якоря
  не идут**: их `price_eff` — это `price_floor_1M`, константа конфига, а не
  рынок. В таблице они остаются, но помечены звёздочкой — их value держится на
  пороге и читается как «бесплатно», а не как измеренная величина.
- В метрику идёт **нижняя граница 95% CI**, а не точечная оценка
  (`scoring.rating_for_metric`, переключается `scoring.rating_basis`). В верхушке
  разрыв между соседями меньше ширины интервала: на срезе 2026-09-02 топ-10
  `overall` укладывается в 20.4 очка при медианной полуширине CI 5.0, и 25 пар
  из 45 внутри топ-10 статистически неразличимы — включая все четыре верхние
  строки. Точечный рейтинг выдавал бы за качество шум выборки голосов. В таблице
  по-прежнему `rating`, рядом с ним `±`.
- Медиана Δ берётся по **рейтингу**, а не по дате: `created` из OpenRouter — дата
  появления слага в каталоге, а не релиза модели.
- `top_n_for_median` (10), `token_share` (0.75 ≈ 3:1 вход:выход) и
  `price_floor_1M` (0.01 — чуть ниже самой дешёвой платной модели рынка,
  $0.025 на 2026-09-08) задаются в конфиге.
- `k` и `γ` задаются **пресетами**. `k` — во сколько раз рейтинг искупает цену,
  **порядок строк задаёт только он**; `γ` растягивает шкалу value вокруг сотни
  (`γ < 1` поджимает распределение), но ранжирование не меняет.

### Пресеты

| Пресет | k | γ | Интерпретация |
|--------|---|---|---------------|
| **quality** | 0.015 | 0.3 | 100 очков Elo ≈ 4.5× цены; шкала плотная, отставание почти не наказывается ценой |
| **balanced** | 0.010 | 0.5 | По умолчанию: 100 очков Elo ≈ 2.7× цены |
| **budget** | 0.005 | 1.0 | 100 очков Elo ≈ 1.6× цены; value линеен по эффективной цене |

Замер на снапшоте 2026-09-08 (`overall`, 175 моделей): пресеты дают разные, но
сильно скоррелированные порядки — τ Кендалла 0.66–0.84, в топ-10 совпадают
6–8 моделей из 10.

**Калибровка `k`.** Ориентир — наклон самого рынка: регрессия `ln(blended_price)`
на рейтинг по платным строкам категории. Он считается на каждом цикле и пишется
в снапшот как `calibration.<вкладка>.market_slope` (отдаётся в `/api/meta`),
поэтому выбор `k` сверяется с данными, а не держится «на глаз». На 2026-09-08
наклон равен 0.0056–0.0069 по вкладкам (`overall` 0.0069, R² 0.16 — рейтинг
объясняет лишь шестую часть разброса цен). Относительно него `budget` (0.005)
идёт вровень с рынком, `balanced` (0.010) в ~1.5 раза круче, `quality` (0.015) —
в ~2.2 раза.

Поднимать `k` заметно выше не помогает, и это **не** вопрос подбора: единственный
`k` задаёт обменный курс сразу на всём диапазоне. Чтобы разрыв топ-10 в 20.4
очка стоил заметных денег (`k` = 0.035 даёт 2.04×), полный размах категории в
417 очков раздувается до 2 200 000×, и усиливается при этом в основном шум:
полуширина CI в топ-10 — ±5.0 очка, то есть полоса неразличимости (±7)
сопоставима с самим разрывом. Поэтому метрика перешла на нижнюю границу CI,
а не на более крутой `k`.

## Конфигурация

Все параметры задаются в [`config.yaml`](./config.yaml) и могут быть переопределены через переменные окружения с двойным подчёркиванием для вложенности (например, `SERVER__PORT=8080`).

### Критические секции конфигурации

- **`scoring.presets`** — веса `k`/`γ` для каждого профиля value (`k` задаёт порядок, `γ` только растягивает шкалу)
- **`scoring.price_floor_1M`** — нижняя граница цены $/1M, чтобы `:free` получали скор, а не `null`
- **`sources.lmarena.categories`** — маппинг вкладок UI на subset'ы датасета и фильтры категорий
- **`model_aliases`** — маппинг имён моделей между LMArena и OpenRouter

> **Важно:** Таблица `model_aliases` — самый хрупкий компонент. Модели без алиаса попадают в множество `unmatched`, видимое через `/api/meta` и `/api/health`. В настоящее время зарегистрировано 35 алиасов; для боевого развёртывания необходимо верифицировать и расширить этот маппинг.

## Рекомендации для боевого запуска

1. **Верификация схемы датасета** — проверить имена колонок и значения категорий перед включением в боевой контур:
   ```bash
   python -c "from app.sources.lmarena import fetch_snapshot as f; \
     b = f('lmarena-ai/leaderboard-dataset', 'text_style_control'); \
     print(b.revision, b.publish_date); print(sorted(b.categories())); print(b.rows[0])"
   ```
   При необходимости обновить константы в `app/sources/lmarena.py` и фильтры категорий в `config.yaml`.
   Неизвестная `category` больше не даёт молча пустую вкладку — воркер пишет
   WARNING со списком категорий, которые в subset реально есть.

2. **Покрытие алиасов** — неполные алиасы приводят к появлению несматченных моделей (отображаются в health-check). Расширять `config.yaml:model_aliases` по мере необходимости.

3. **Персистентность кэша** — файловый кэш (`data/snapshot.json`) сохраняется при перезапуске контейнера, если смонтирован как Docker volume (настроено в `docker-compose.yml`).

4. **Лицензионная чистота** — перед публичным развёртыванием проверить условия использования датасетов LMArena и API OpenRouter.
