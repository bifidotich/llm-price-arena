# LLM Value Tracker — SPEC

Веб-сервис, который собирает Elo-рейтинги моделей (LMArena) и цены (OpenRouter),
матчит их по именам, считает **Value Score** и отдаёт через REST API + статичный
дашборд. Данные обновляются по расписанию и кэшируются; падение источника не роняет
сервис.

---

## 1. Источники данных

| Что | Откуда | Как |
|-----|--------|-----|
| Рейтинги (Elo) | HuggingFace dataset `lmarena-ai/leaderboard-dataset` | parquet сплита по HTTP с пином commit sha (`lmarena.fetch_snapshot`), фильтр по `category` — в памяти |
| Цены | OpenRouter `GET /api/v1/models` | `pricing.prompt` / `pricing.completion` — цена за **токен**, привести к $/1M (× 1e6) |

**Не** парсить HF Space `lmarena-ai/arena-leaderboard` — это iframe-обёртка вокруг
сайта, данных оттуда удобно не достать.

Категории вкладок UI — это не отдельные subset'ы датасета, а `category` внутри
текстовой арены (+ `webdev` как отдельная арена для кода). Маппинг
`вкладка → (subset, category)` задаётся в конфиге, не хардкодится.

### Главный риск — маппинг имён

Имена не совпадают: LMArena `claude-opus-4-6-thinking` ↔ OpenRouter
`anthropic/claude-opus-4.6`. Часть моделей (preview / thinking-варианты) на
OpenRouter может вообще отсутствовать. Поэтому:

- `model_aliases` в конфиге — ядро, не опция.
- Несматченные модели **не выбрасываются молча** — попадают в `unmatched` снапшота
  и в `/api/health`.

## 2. Value Score

Метрика считается в две ступени: сначала цена приводится к качеству, потом
нормируется внутри категории.

```
quality   = rating_lower  (rating_basis: lower)             # нижняя граница 95% CI
M_top_N   = median(top_n лучших по quality)                 # якорь Δ
Δ         = quality - M_top_N                               # расстояние до якоря
price     = token_share·input + (1 - token_share)·output    # $/1M, средневзвешенная
floored   = price < price_floor_1M                          # цену подменил порог
price     = max(price, price_floor_1M)                      # :free не делит на ноль
price_eff = price · e^(-k·Δ)                                # $/1M при качестве якоря
P_anchor  = median(price_eff по строкам с floored = false)  # якорь шкалы value
value     = 100 · (P_anchor / price_eff)^γ                  # 100 = медиана категории
```

- **`price_eff`** — «сколько стоила бы модель, будь у неё рейтинг якоря».
  Остаётся в долларах и пишется в снапшот как `effective_price_1M` по каждому
  пресету: это то, что читается глазами, в отличие от индекса.
- **`value`** — «сколько процентов от эффективности медианной модели
  категории». 100 — как у медианы, больше — выгоднее её, меньше — дороже.
  Сверху не ограничен; сравним **внутри одной категории и одного пресета**.
- Якорь шкалы — **медиана, а не минимум**. Минимум держала одна произвольная
  строка, поэтому появление в категории аномально дешёвой модели двигало value
  всем остальным; на снапшоте 2026-09-08 сотню забрал `thinkingmachines/inkling:free`,
  и весь фронтир сплющился в 3–4 балла.
- Строки с `floored = true` (`price_is_floored` в снапшоте) **в выборку якоря
  не идут**: их `price_eff` — это `price_floor_1M`, константа конфига, а не
  рынок. В таблице они остаются, но помечены звёздочкой — их value держится
  на пороге и читается как «бесплатно», а не как измеренная величина.
- В метрику идёт **нижняя граница 95% CI**, а не точечная оценка
  (`scoring.rating_for_metric`, переключается `scoring.rating_basis`). В верхушке
  таблицы разрыв между соседями меньше ширины интервала: на срезе 2026-09-02
  топ-10 `overall` укладывается в 20.4 очка при медианной полуширине CI 5.0, и
  25 пар из 45 внутри топ-10 статистически неразличимы (критерий
  `|Δ| > √(hw_i² + hw_j²)`) — включая все четыре верхние строки, неотличимые
  от лидера. Точечный рейтинг выдавал бы за качество шум
  выборки голосов; нижняя граница отбирает кредит у моделей, которые лидерства
  ещё не доказали числом голосов. В таблице по-прежнему показывается `rating`,
  рядом с ним — `±`.
- Медиана Δ берётся по **рейтингу**, а не по дате: `created` из OpenRouter — дата
  появления слага в каталоге, а не релиза модели, и якорь метрики от неё
  зависеть не должен.
- `top_n_for_median` (10), `token_share` (0.75 ≈ 3:1 вход:выход) и
  `price_floor_1M` (0.01 — чуть ниже самой дешёвой платной модели рынка,
  $0.025 на 2026-09-08) задаются в конфиге. Порог нужен, чтобы `:free` попадали
  в метрику, а не в `None`.
- `k` и `γ` задаются **пресетами**. `k` — во сколько раз рейтинг искупает цену;
  **порядок строк задаёт только он**. `γ` — растяжение шкалы value: `γ < 1`
  поджимает распределение к сотне, но ранжирование не меняет.

| Пресет | k | γ | Смысл |
|--------|---|---|-------|
| `quality`  | 0.015 | 0.3 | 100 очков Elo ≈ 4.5× цены; шкала плотная, отставание почти не наказывается ценой |
| `balanced` | 0.010 | 0.5 | дефолт: 100 очков Elo ≈ 2.7× цены |
| `budget`   | 0.005 | 1.0 | 100 очков Elo ≈ 1.6× цены; value линеен по эффективной цене |

Замер на снапшоте 2026-09-08 (`overall`, 175 моделей): пресеты дают разные, но
сильно скоррелированные порядки — τ Кендалла 0.66–0.84, в топ-10 совпадают
6–8 моделей из 10.

### Калибровка `k`

Ориентир — наклон самого рынка: регрессия `ln(blended_price)` на рейтинг по
платным строкам категории. Он считается на каждом цикле и пишется в снапшот как
`calibration.<вкладка>.market_slope` (отдаётся в `/api/meta`), поэтому выбор `k`
можно сверить с данными, а не держать «на глаз».

На 2026-09-08 наклон равен 0.0056–0.0069 по вкладкам (`overall` 0.0069, R² 0.16
— рейтинг объясняет лишь шестую часть разброса цен). Относительно него `budget`
(0.005) идёт вровень с рынком, `balanced` (0.010) в ~1.5 раза круче, `quality`
(0.015) — в ~2.2 раза.

Поднимать `k` заметно выше не имеет смысла, и это **не** лечится подбором:

| `k` | топ-10 (20.4 очка) | полный размах (417 очков) |
|-----|--------------------|----------------------------|
| 0.005 | 1.11× | 8× |
| 0.010 | 1.23× | 65× |
| 0.020 | 1.50× | 4 200× |
| 0.035 | 2.04× | 2 200 000× |

Единственный `k` задаёт обменный курс сразу на всём диапазоне. Чтобы 20 очков
разрыва в верхушке стоили заметных денег, полный размах категории уходит в
нечитаемые множители — и наказывается при этом в основном шум: ширина CI в
топ-10 (±5 очков, то есть полоса неразличимости ±7) сопоставима с самим
разрывом. Отсюда `rating_basis: lower` выше — вместо усиления шума метрика
перестаёт платить за неподтверждённое лидерство.

## 3. Архитектура

```
                ┌──────────── worker (APScheduler) ────────────┐
                │  каждые refresh_interval:                     │
LMArena HF ─────┤   1. fetch ratings (latest)                   │
OpenRouter  ────┤   2. fetch prices                             │──► Cache
                │   3. match по aliases → blended_price, value  │    (snapshot.json)
                │   4. atomic write snapshot                    │
                └───────────────────────────────────────────────┘
                                                                      │
   static dashboard ──GET /api/models?category=&preset=───────────► FastAPI ◄┘
                    ──GET /api/health, /api/meta──────────────►
```

Сервис стартует с последним снапшотом из кэша (если есть), worker обновляет в фоне.
Первый прогрев — при старте, если кэш пуст.

## 4. Запуск

```bash
git clone <repo> && cd llm-value-tracker
cp .env.example .env        # при необходимости вписать HF_TOKEN
docker compose up
# UI:   http://localhost:8000
# API:  http://localhost:8000/api/models?category=coding&preset=balanced
```

Вся конфигурация — `config.yaml` + переопределение через env. Тот же образ
поднимается на внешнем хостинге (порт/конфиг наружу через env).

---

## 5. API

| Метод | Ответ |
|-------|-------|
| `GET /api/models?category=&preset=` | отсортированный список: rating, input/output/blended price, value |
| `GET /api/health` | статус + время последнего успешного фетча каждого источника + кол-во unmatched |
| `GET /api/meta` | список категорий, пресетов, версия/время снапшота |

---

## 6. Кэш / хранение

Абстрактный интерфейс `Cache`. Старт — `FileCache` (`data/snapshot.json`, атомарная
запись через temp + rename). Позже без переписывания логики подменяется на
Redis/SQLite. Снапшот хранит: модели по категориям, время обновления, статус
источников, список unmatched.

---

## 7. Вне MVP

- Публичный доступ: хостинг, healthcheck, rate-limit на API.
- Файловый кэш → Redis.
- История во времени: датасет даёт `full` split → график «рейтинг/value во времени».
- **Лицензия:** перед публичным развёртыванием свериться с актуальными условиями
  использования LMArena dataset и OpenRouter API (на момент написания лицензия
  датасета обсуждалась в HF discussions).
